# R08 SSV Trust Boundary

- The pinned v7.0 GDScript signal `rewarded_ad_user_earned_reward(ad_info, reward_data)` is a client-side earned event. The inspected wrapper does not expose AdMob's SSV `transaction_id` or a cryptographically verified receipt. Never pass this event directly into the production `verified_rewarded` payout seam.
- The plugin exposes `LoadAdRequest.set_custom_data()` and `set_user_id()` and the debug/release AARs contain SSV `ServerSideVerificationOptions.Builder.setCustomData` references. This proves static API/binary presence only; it does not prove runtime attachment or delivery.
- Safe future flow: authenticated backend issues a single-use opaque claim nonce bound to account, placement, configured item/amount, expiry and `consumed=false`; the client attaches only that nonce as AdMob `custom_data` before requesting/showing the ad. Do not place names, emails, credentials or raw account IDs in `custom_data`/`user_id`.
- Google sends SSV to an owner-configured HTTPS callback. Preserve the raw query bytes/order, verify its ECDSA/SHA-256 signature with Google's rotating public key for `key_id`, validate app/ad unit, claim nonce hash, user binding, reward item/amount, timestamp and unique transaction ID. Atomically consume the claim and write one durable server entitlement. A verified duplicate is idempotent. On client callback, show pending/verification UI; reconcile valuable balances only from an authenticated server entitlement response.
- Existing `tests/backend_protocol/m34_r06_ssv_backend_mock.test.js` passed 8/8 using ephemeral local ECDSA keys and in-memory state. It is protocol-model evidence, not a deployed verifier, real Google callback, backend, or payout acceptance.
- No backend host, account-authentication contract, production AdMob account/ad-unit/callback registration, durable reward database, secret store, privacy/age/consent ruling, or deployment was selected or configured. No paid service was deployed. Production ad payout and IAP remain disabled.

Sources: `evidence/M34-R05/admob_v7_ssv_api_evidence.json`, `evidence/M34-R06/ssv_trust_blueprint.md`, and `tests/backend_protocol/m34_r06_ssv_backend_mock.test.js`.
