## BUILDER CLAIMS VS REPOSITORY TRUTH

### Claim: 387 mandatory assets are complete

**Not accepted as final-quality completion.**

The repository contains a generator that intentionally funnels many distinct assets through one function:

`generic_element(theme, stem, size, group)`

The function creates broad families from a few repeated primitives:
- stars/milestones/finale use the same star motif;
- toggles/badges/status items use one rounded pill + dot;
- effects use one ring/rays construction;
- many semantic icons use one circular frame plus a generic central symbol;
- panels/cards/frames/slots/tracks/tabs/titles use one rounded-panel template;
- unmatched assets use a fallback rounded badge with the asset filename/stem written into it.

That is directly incompatible with locked criterion C03:

> Placeholder rectangles, duplicated files renamed as distinct assets, empty/near-empty PNGs, text-only stand-ins, or obvious temporary mocks do not count as final assets.

The fallback's own source comment calls it a “fallback”. Naming it “illustrated badge” does not convert it into final screen-specific art.

### Claim: complete visual asset production

**Not accepted.**

The production system provides a coherent prototype/UI kit, but not the requested full production visual library.

## FILE / SYMBOL EVIDENCE

### 1. `tools/ui_assets/generate_assets.py::generic_element`

Blocking finding.

Examples:
- `settings_icon`, `map_icon`, `info_icon`, `help_icon`, `sound_icon`, `music_icon`, `haptic_icon`, `language_icon`, `privacy_icon`, `accessibility_icon`, `share_icon`, and `friend_icon` are routed through the same generic icon branch unless one of a tiny set of special cases applies.
- The generic icon branch otherwise renders effectively the same head/body-like mark inside a circle. These icons therefore do not communicate their required meanings.
- Unrecognized assets are rendered as a generic badge with `stem.replace("_", " ").upper()` written on the graphic. This is explicitly a programmer-art fallback.

This fails E05 and C03.

### 2. `tools/ui_assets/generate_assets.py::rounded_panel`

Many visually different product surfaces are reduced to the same rounded-panel construction with changes in label/fill.

Reusable primitives are valid for truly reusable UI bases. They are not sufficient as the final art for every distinct screen/control family when the full manifest requested final-quality assets.

### 3. `tools/ui_assets/generate_assets.py::themed_background`

Main menu, island gameplay/map backgrounds, shop/daily and other “background” outputs are generated from a shared gradient/water-band/palm-line recipe.

The result is thematically coherent, but this does not satisfy the requested complete screen-specific visual production. The world map, shop, daily reward, splash, gameplay, and other background roles need distinct compositions, not primarily palette/variant changes to one shared template.

### 4. `tools/ui_assets/generate_assets.py::island_icon`

All island icons share one fixed island/mountain composition plus palette and text.

This is insufficient for the required ten distinct island identities. A Frozen Paradise island, Volcano Bay island, Billionaire Island, Tiki Island, etc. must be identifiable from silhouette/composition/material motifs, not primarily color and a written first word.

### 5. `tools/ui_assets/generate_assets.py::table_image`

PASS on geometry, FAIL/PARTIAL on art identity.

All tables correctly share a common mask. That requirement must be preserved.

However, most table skins are essentially:
- the same gradient;
- same sparse grain;
- same edge/trim;
- same repeated perspective lines;
- palette changes.

Only a few islands receive extra specific treatment:
- Party Beach / Final Island extra accent lines;
- Volcano Bay lava lines.

Tiki, Azure, Coconut, Sunset, Frozen, Billionaire, and Sunny Cove need more convincing material/surface/motif identity while keeping the exact same silhouette.

### 6. `owner_logo_variant`

PASS.

Source-level implementation uses the supplied owner logo and proportional resizing. No generative redesign path is present.
