## Implementation summary

- The test-only AdMob request now uses the currently authenticated subject as `LoadAdRequest.user_id` and the claim nonce as `custom_data`. It verifies the claim subject against the active authenticated transport subject and binds request platform, placement, app ad unit, amount, nonce, session, and business transaction before asking the bundled SDK to load. The request probe instantiates the installed `LoadAdRequest.gd` model and checks its serialized fields. Native SDK bridge delivery of those fields has not been validated on a device; no native-ready claim is made.
- Worker policy now requires separate exact values for the app request's full AdMob unit and Google's signed SSV `ad_unit`. The signed callback is checked against the per-claim numeric SSV unit, authenticated user, nonce, reward item, and amount. Migration `0002` leaves older claims with an empty callback unit so they fail closed. Worker queue insertion enforces an atomic cap of 50 active claims plus unacknowledged rewards per user.
- Pending reward transport now requires explicit identity-to-active-save binding and rechecks it at response/application time. Completion callbacks snapshot and clear only the completed operation state before emitting signals, preventing a synchronous pending callback from erasing a newly initiated ACK's transaction binding.
- `CampaignNavigationController` retries pending reconciliation after setup and after Energy drops below cap. Full-cap Energy remains ungranted/unacknowledged and reports a retry condition. The async controller probe covers two server rows, persistence before asynchronous ACK, ACK network failure, restart/replay without a second grant, profile mismatch, subsequent ACK/fetch sequencing, and final SaveManager state. Durable delivery probes also cover failed save rollback and successful recovery using the same server transaction, daily slots 2-5, and UTC midnight.
- The Play Billing test adapter requires a durable verifier completion journal before provider ACK/consume, recovers pending completion rows on restart, and finalizes journal entries after the provider callback. The local fake verifier test proves replay/idempotency across adapter recreation. No production store verifier/backend endpoint is configured; all catalog products remain non-buyable.
- Production ads and purchases remain disabled. No game physics, visuals, XTool/BAT, or iPhone IPA upload system was changed.
