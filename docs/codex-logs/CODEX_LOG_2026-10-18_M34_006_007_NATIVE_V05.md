## Implementation summary

- Added durable client delivery of verified Worker SSV rewards. The game validates the authenticated subject, row schema, placement, reward item and exact amount; the server transaction ID is the deduplication key. For daily rewards, a UTC date/slot client transaction ID preserves the daily slot ledger independently from the SSV receipt ID. Energy-cap rows remain unacknowledged until applicable.
- Delivery persists canonical campaign state before sending the server ACK. Failed persistence rolls back in-memory economy state; repeated delivery skips a second grant and retries ACK. Pending Worker delivery can be reconciled after process restart.
- Added an HTTPS-only HTTP transport with no embedded endpoint, bearer secret, or identity. It stays disabled unless the owner supplies an external identity provider and explicitly enables it. The consent assertion and UMP state are request inputs only; they are not independent compliance proof.
- Added a test-only AdMob adapter using the installed plugin's documented API/signal names and platform TEST rewarded IDs. It handles load, load-failure, earned, dismiss and show-failure callbacks, rejects stale/double callbacks, and never grants currency from the native earned callback. Claims still require authenticated HTTPS Worker transport.
- Added a debug-only Play Billing adapter around the installed `BillingClient` integration surface. Pending or unverified purchases do not grant or acknowledge/consume. Verified purchases use the server-verifier gate; consumables consume and non-consumables acknowledge after verification. The existing catalog remains non-buyable without verified product configuration.
- The StoreService provider/verifier injection boundary can host a StoreKit implementation, but no StoreKit adapter or Apple build was produced. No Apple Merchant ID is used for StoreKit.
